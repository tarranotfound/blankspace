# Contributing to Blankspace

Thanks for checking out Blankspace. This is a personal Arch Linux / Hyprland rice and an open-source project I am building while learning.

## Before contributing

- Keep the clean black-and-white direction with subtle green accents.
- Test configuration changes on your own system when possible.
- Do not commit personal paths, secrets, cache files, or backup files.
- Keep changes focused on one component or problem.
- Explain why a change is useful instead of only changing the appearance.

## Reporting a problem

When opening an issue, include:

- Which component is affected.
- Your distro and relevant package versions.
- The error message or command output.
- What you expected to happen.
- What actually happened.

Screenshots are useful for visual issues.

## Pull requests

For a pull request, explain:

1. What changed.
2. Why the change was made.
3. Which files were changed.
4. Whether the change was tested.

Include screenshots when the visual result matters. Please avoid unrelated formatting changes so the history stays easy to follow.

## Notes

Blankspace is hardware- and setup-specific in places. A change that works on one machine may need adjustments on another, so test carefully and mention any limitations.
